# Requirements: UNO Pop Deck Simulator — Visual/UX Polish Milestone

**Defined:** October 20, 2026
**Core Value:** The app must feel like a deliberately designed, playful-but-modern product — satisfying to draw a card, visually cohesive — without breaking any existing gameplay, offline, or install behavior.

## v1 Requirements

Requirements for this polish milestone. Each maps to a roadmap phase.

### Foundation (Theme & Tokens)

- [x] **FND-01**: A single soft neo-brutalist theme is defined entirely via CSS custom properties in `:root` (palette, spacing, radius, outline width, shadow, motion durations)
- [x] **FND-02**: The app background uses a cream base with a subtle dot pattern (pure-CSS)
- [x] **FND-03**: Panels, cards, buttons, and chips share a consistent thin rounded black outline + rounded-corner visual language
- [x] **FND-04**: The palette defines a yellow brand color and three functional accents — Aman = green, POP! = red, UNO! = gold — with text/surface pairings that meet WCAG AA contrast

### Typography

- [x] **TYP-01**: A rounded, playful display font is self-hosted (woff2) and applied to headings/display text, with a sensible fallback stack
- [x] **TYP-02**: The self-hosted font is registered in the service-worker precache and loads correctly offline (`CACHE_NAME` bumped)
- [x] **TYP-03**: Typographic hierarchy and spacing are applied consistently across the app (titles, labels, counts, status)

### Core Surfaces

- [x] **CARD-01**: The active card is restyled to the new theme while the existing 3D flip animation still plays on every draw
- [x] **CARD-02**: The UNO! card gets a distinct "special" gold treatment (e.g. sheen/glow/outline) so it reads as rare and does not blend with the brand yellow
- [x] **CARD-03**: The idle/empty card state (`?`) is redesigned to feel inviting
- [x] **PANEL-01**: The status panel (sisa deck / akumulasi / status message) is restyled to feel designed rather than form-like
- [x] **BTN-01**: Action buttons (Ambil Kartu / Reset / Atur Deck) are restyled as outlined pill buttons with clear press feedback
- [x] **HIST-01**: The history panel and history chips are restyled consistently in the accent colors

### Deck Builder

- [x] **DECK-01**: The custom deck-builder panel and its number inputs are restyled to match the theme (replacing the dashed border / plain inputs)
- [x] **DECK-02**: The deck-builder panel open/close is driven by a CSS class (not inline `style.display`) and animates smoothly open/closed
- [x] **DECK-03**: Existing deck-builder functionality (configuring card counts and Simpan & Reset) continues to work unchanged

### Big Moments & Micro-interactions

- [x] **FX-01**: Drawing a UNO! card triggers a celebratory confetti/particle burst (implemented with no runtime CDN dependency)
- [x] **FX-02**: Drawing a POP! card triggers a subtle screen-shake effect
- [x] **FX-03**: Micro-interactions/transitions are added (button press, panel open/close, history item entrance) using GPU-friendly `transform`/`opacity`
- [x] **FX-04**: Any new animation asset (e.g. a confetti library) is vendored locally and added to the service-worker precache (`CACHE_NAME` bumped)

### Accessibility & Motion

- [x] **A11Y-01**: All non-essential motion (confetti, screen shake, entrances, idle motion) is reduced or disabled under `@media (prefers-reduced-motion: reduce)`, while gameplay remains fully usable

### Preservation (Regression Guards)

- [x] **PRES-01**: Existing audio SFX (draw / POP! / UNO!) continue to work after the redesign
- [x] **PRES-02**: Existing haptic feedback (`navigator.vibrate`) continues to work
- [x] **PRES-03**: Game state persistence (localStorage resume on reload) continues to work
- [x] **PRES-04**: The app remains an installable, offline-capable PWA after first load (all required assets precached)

### Quality & Housekeeping

- [x] **QA-01**: Layout works on small mobile screens (~360px wide): no horizontal scroll and tap targets stay ≥44px
- [x] **QA-02**: README is updated to reflect the current feature set and new visual design

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Multiplayer / multiple players at a table | User explicitly deferred; milestone is single-player polish only |
| New gameplay rules, scoring, or card types | This is a visual/UX pass, not a gameplay change |
| Light/dark theme toggle | User chose a single theme only |
| Backend, accounts, cloud sync, online features | App is intentionally standalone/offline-first |
| Build tooling / framework migration (React, bundlers, npm build) | Must stay runnable on mobile with no install; vanilla static architecture preserved |
| Runtime CDN-dependent libraries or webfonts | Would break the offline PWA guarantee; assets must be vendored + precached |
